# 官网本地化规则

官网仍由 Cloudflare Pages 从仓库根目录直接部署，不在 Pages 增加构建服务。发布前在本地运行确定性生成器，把四语页面作为静态文件提交：浏览器、搜索引擎和分享抓取器读到的首个 HTML 就是对应语言，不依赖客户端翻译。

## 内容与生成物

- 根目录 `index.html`、`welcome.html`、`updates.html`、`pricing.html`、`downloads.html`：页面结构的唯一编辑入口，同时也是无 JavaScript 时可阅读的英文中立入口。新增用户可见文案应加 `data-key`，替代文本用 `data-alt-key`，读屏名称用 `data-aria-label-key`；不要单独编辑生成页中的译文。
- `components/navbar.html`、`components/footer.html`、`components/download-dialog.html`：共享结构。品牌、平台名、用户数据字段和文件格式保持原名。
- `locales/{en,zh-CN,ja,es}.json`：共享与各页词条，以及每页标题、描述。词条是受信任的仓库内容；含 HTML 的词条须人工审阅标记，不接受用户输入。
- `updates-data.json`：全部历史版本记录的唯一数据文件。`desktopUpdates` 保存桌面端记录，`updates` 保持为插件发版工具拥有的插件记录；两个数组各自按新到旧排列，版本号可重复于不同产品。默认打开桌面端页签。页签链接保留产品锚点，两区正文都静态生成，脚本未运行时也可直接阅读。只有确实没有条目时显示对应产品空态。新记录的日期、摘要和功能标题/说明须有四语；旧记录只翻译当时的事实。
- `scripts/build-localized-pages.mjs`：生成根目录中立英文入口、`en/`、`zh-CN/`、`ja/`、`es/` 各五页和 `sitemap.xml`。这些 HTML 与 sitemap 是派生部署资产，必须与源文件一同提交。`updates-renderer.js` 供静态生成器渲染两端更新记录，浏览器直接读取静态正文。

四种语言各有稳定地址：`/{locale}/`、`/{locale}/welcome`、`/{locale}/updates`、`/{locale}/pricing`、`/{locale}/downloads`。根目录 `/`、`/welcome`、`/updates`、`/pricing`、`/get` 是兼容和自动语言选择入口，不是任何语言的规范地址；下载页的 `/get` 避开旧产品拥有的 `/download*` 路由。实际仓库文件带 `.html`，Cloudflare Pages 提供无扩展名访问。每个语言页面有自指 canonical、四语互相指向的 `hreflang`，`x-default` 指向对应中立入口；sitemap 只列 20 个规范地址。每种语言的标题、描述、Open Graph、正文及首页结构化 FAQ 都写在该地址的 HTML 中。

## 语言选择与回退

营销页由 `build:i18n` 扫描生成后的四语标记和页面交互，构建一份内容版本化的 `resource/marketing-utilities.css`。页面直接加载静态样式，不再通过 CDN 执行 Tailwind。英文兜底词包和当前语言词包并行加载，静态正文在词包失败时保持可读。

中立入口的生成页在 `<head>` 开头内联同一个 `site-i18n.js` 路由实现，先根据下列优先级定位规范地址，再加载目标页资源。原有查询参数（消费掉的 `lang` 除外）和锚点随自动跳转保留。规范页仍加载版本化的语言脚本，禁用 JavaScript 时中立入口保留完整英文正文。

明确的语言路径优先；旧 `?lang=` 链接其次；随后是用户手动保存的官网偏好、浏览器语言；不支持的语言最终用英文。`ja-JP`、`es-MX` 等地区变体归入基础语言。客户端把旧入口或自动检测结果导航到规范语言路径；只有用户在菜单中切换语言才保存偏好。内部链接始终指向当前语言的静态页面。

顶部导航在桌面和移动端共用一个语言入口。展开的四语菜单使用官网导航控件的字号、圆角和选中态；当前语言明确标记，点击外部、按 Escape 或移出键盘焦点时收起。菜单外观不交给浏览器原生 `<select>` 弹层决定。`site-nav.js` 统一管理语言与移动导航两个菜单的开合、互斥和键盘交互；`site-i18n.js` 只决定语言、词条与当前语言标记。

生成时缺少词条会失败，不能发布半译页面。运行时英文词包缺失时保留已经生成的静态页面；某个非英语词包加载失败时也保留该语言页面与导航，不错误覆盖为英文。浏览器脚本不是首屏译文的前提。新增语言应补齐一个词包，并更新支持列表、生成器、测试与 sitemap；不要复制页面脚本。

业务逻辑和埋点不依赖翻译后的按钮文字；链接目标等稳定语义决定事件，`ui_language` 只是分析维度。只有规范语言页产生 GA 的 `page_view`，旧入口跳转不计入一次额外浏览。

官网导航和首页保留 `/desktop/download?link=website`，四语下载页提供 `/desktop/download/mac` 与 `/desktop/download/win` 显式入口。`site-download.js` 在用户点击后调用下载网关的准备接口，成功时在当前页面交给浏览器，无法识别系统或准备失败时显示系统选择弹窗。关闭脚本时仍保留原生链接，但失败由下载服务直接呈现。Chrome／Edge 链接继续指向各自官方商店。浏览器接管文件传输后的断网无法由页面可靠感知。官网部署必须晚于提供准备接口的下载网关，正式部署前需核验两端镜像、GitHub 备用和四语交互；当前仅本地候选。

## 发版与验收

官网独立发布与部署回执见 [RELEASES.md](RELEASES.md)。官网自身页面变化直接在本仓处理；桌面端更新条目按 Desktop 的已确认 `releases/<version>.json` 和实际公开结果整理到 `updates-data.json` 的 `desktopUpdates`，当前由人工核对同步。浏览器插件的 `doc/release-entry-{version}.json` 是其官网四语记录与四语商店说明的共同输入；插件仓 `scripts/prepare_release.py --write` 只更新插件条目，不改官网 HTML 或桌面版本。三类变化均在本仓执行以下生成与检查，不相互触发安装包或商店发布：

```sh
npm ci
npm run build:i18n
npm test
npm run check:i18n
```

核对 `updates-data.json` 与派生的四语 `updates.html` 一起进入官网提交，再推送官网 `main`；生产部署后逐语言检查首响应、版本条目、语言切换和错误路径的 404。Cloudflare Pages 本身仍无构建命令。当前 v1.5.0 及更早历史条目已补齐四语，不重打旧商店包或改写旧 Tag。

每次改译文，让未参与翻译的人以当地读者视角检查事实、语气、术语和窄屏排版；键位齐全不代表译文自然。本地可用 `npx wrangler pages dev . --port 43135 --compatibility-date=2026-04-12` 或其他模拟静态路径的服务器验收；普通 `python3 -m http.server` 不提供 Pages 的无扩展名路由。浏览器检查首页、欢迎页、更新记录、定价、下载页、语言切换、导航及窄屏。

本契约覆盖官网四语营销页面及下述双语法律页面的语言规则与静态首响应，不等于建立了 Markdown 版网页、`llms.txt` 或 Agent 内容协商能力。

## 桌面版法律页面的双语范围

桌面版隐私政策与用户协议只提供中英文，具体源版本、发布及审阅规则见`doc/DESKTOP-LEGAL.md`。规范地址为`/{en|zh-CN}/desktop/{privacy|terms}`，原`/desktop/{privacy|terms}`为英文静态兜底和自动语言入口；其他官网语言回退英文。法律文档复用`site-i18n.js`的路由、语言优先级和官网偏好，只以已审阅的静态正文呈现，不加载营销词包。右上角语言图标打开中英文下拉菜单，复用`site-nav.js`的开合与键盘交互，不显示尚未翻译的语言。正文在无脚本时仍可阅读，下拉菜单需要脚本。正式文档可收录，sitemap继续由现有营销页生成器维护。
